# Watermark Remover (тестовый проект)

Простое Android-приложение: выбираешь видео → рамкой выделяешь текст/вотермарк →
жмёшь "Применить" → на выходе .mp4 в 1080p без выделенной области
(закрашено методом delogo — интерполяция по соседним кадрам/пикселям).

## ⚠️ Почему это исходники, а не готовый APK

Я собираю этот ответ в изолированном окружении без доступа в интернет и без
Android SDK/Gradle — физически не могу скомпилировать .apk и прислать его
файлом. Зато это полный рабочий исходный код проекта: открываешь в Android
Studio → Build → APK готов за пару минут, как ты и делал с JARVIS.

## Как собрать

1. Открой папку `WatermarkRemover` в Android Studio (Open → выбрать папку).
2. Дай Gradle синхронизироваться (скачает зависимости).
3. **Важно про FFmpeg-зависимость**: в `app/build.gradle.kts` подключена
   `com.arthenica:ffmpeg-kit-full-gpl:6.0-2`. Официальный репозиторий
   ffmpeg-kit заброшен автором в 2025 — на момент сборки проверь, доступен
   ли этот артефакт в Maven Central / JitPack. Если нет — варианты:
   - поискать актуальный community-форк ffmpeg-kit на GitHub/JitPack
     (обычно достаточно поменять координаты зависимости на форк);
   - либо собрать свой минимальный `.aar` из исходников FFmpeg
     (дольше, но самый надёжный вариант в долгосрочной перспективе).
4. Build → Build Bundle(s)/APK(s) → Build APK(s).
5. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk` — закинь на
   телефон и установи (разреши установку из неизвестных источников).

## Как это работает

- `MainActivity` — меню, кнопка "Добавить видео" (через системный picker).
- `EditorActivity` — превью видео (`VideoView`) + `MaskOverlayView` поверх
  него: тянешь пальцем прямоугольник по тексту/вотермарку.
- При нажатии "Применить" координаты рамки (в пикселях экрана)
  пересчитываются в реальные пиксели видео, дальше `VideoProcessor`
  запускает FFmpeg с фильтром:
  ```
  delogo=x=..:y=..:w=..:h=..:show=0,scale=-2:1080
  ```
  `delogo` закрашивает область на основе окружающих пикселей/кадров,
  `scale=-2:1080` приводит результат к высоте 1080p с сохранением
  пропорций.
- Результат сохраняется в
  `Android/data/com.akula.watermarkremover/files/Movies/watermark_removed/`.

## Новое: трекинг маски по кадрам

Если вотермарк двигается по видео:
1. Выдели рамку в начальный момент → жми "Добавить точку трекинга".
2. Перемотай видео сикбаром на другой момент, где вотермарк уже в другом
   месте → снова выдели рамку → снова "Добавить точку трекинга".
3. Повтори столько раз, сколько нужно для плавного отслеживания
   (обычно 3-6 точек достаточно даже для сложного движения).
4. Между точками координаты маски линейно интерполируются — это не
   настоящий CV-трекинг (нейросеть не "видит" сам вотермарк), а просто
   геометрическое движение между отмеченными позициями. Работает хорошо,
   если вотермарк движется предсказуемо (по прямой/плавно); если он
   скачет хаотично — добавляй больше точек.

Если оставить только одну точку (или не жать кнопку вообще, а просто
нарисовать рамку) — маска статична на всё видео, как в первой версии.

## Новое: два режима закрашивания

- **Быстро (delogo)** — как раньше, FFmpeg-фильтр `delogo`. Работает
  быстро, но на сложном фоне может оставлять смазанное пятно.
- **Качественно (нейросеть)** — каждый кадр прогоняется через модель
  image-inpainting (LaMa) на устройстве через ONNX Runtime. Реалистичнее
  достраивает фон, но значительно медленнее (CPU-инференс покадрово).

### Модель для inpainting (нужно добавить самому)

Веса модели не входят в исходники — в этом окружении нет доступа в
интернет, чтобы их скачать и вшить за тебя. Что нужно сделать:

1. Найди готовый ONNX-экспорт LaMa (модель Apache-2.0, есть публичные
   конвертации, например в проектах вида `lama-cleaner` / `iopaint` —
   поищи "big-lama onnx" на GitHub/Hugging Face).
2. Положи файл как `app/src/main/assets/lama.onnx`.
3. Открой файл в https://netron.app и проверь реальные имена входов/
   выходов тензоров — в `NeuralInpainter.kt` есть константы
   `INPUT_IMAGE_NAME`, `INPUT_MASK_NAME`, `OUTPUT_NAME` — поправь их,
   если у твоего конкретного экспорта имена отличаются от `image`/
   `mask`/`output`.
4. Проверь ожидаемый размер входа модели (обычно 512x512) — если другой,
   поменяй `MODEL_INPUT_SIZE`.

### Производительность на HONOR X9c

Snapdragon 6 Gen 1, CPU-инференс — рассчитывай на несколько секунд на
кадр в "качественном" режиме. Для 10 секунд видео на 30fps это 300
кадров → реально несколько минут обработки. Прогресс-бар показывает
номер кадра, чтобы было видно, что процесс идёт, а не завис.

Если после теста скорость будет неприемлемой — следующий логичный шаг:
обрабатывать не каждый кадр, а через один-два и переиспользовать
результат для пропущенных (заметно быстрее, чуть хуже на резких сценах
с движением) — могу добавить эту оптимизацию отдельно, если понадобится.

## Автосборка APK в облаке (GitHub Actions)

Чтобы не ставить Android Studio, можно собирать APK автоматически в
облаке при каждом пуше кода в GitHub — файл `.github/workflows/build-apk.yml`
уже в проекте, настроен.

### Разовая настройка (5-10 минут)

1. Создай пустой репозиторий на github.com (можно приватный — Actions
   работает и в приватных репозиториях, 2000 бесплатных минут в месяц
   на бесплатном тарифе, этого более чем достаточно).
2. Залей туда содержимое папки `WatermarkRemover` — можно прямо с
   телефона через приложение GitHub (New → Repository, потом
   Add file → Upload files, закинуть весь проект как есть, включая
   скрытую папку `.github`), либо с компьютера через git:
   ```bash
   cd WatermarkRemover
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_ЛОГИН/watermark-remover.git
   git push -u origin main
   ```
3. На вкладке **Actions** в репозитории появится workflow "Build APK" —
   запустится сам после пуша (или жми "Run workflow" вручную).

### Дальше при каждом изменении

1. Заливаешь новую версию кода в репозиторий (push или загрузка файлов
   через приложение/сайт GitHub).
2. Через 2-4 минуты в разделе **Actions → Build APK → (последний запуск)
   → Artifacts** появится `app-debug-apk` — скачиваешь zip, внутри
   готовый `app-debug.apk`.
3. Устанавливаешь на телефон как обычно.

Если в проекте есть нейросетевой режим (`lama.onnx` в assets) — не забудь
залить и его вместе с кодом, иначе "Качественный" режим не соберётся
рабочим (модель нужна на этапе рантайма, не сборки, но файл должен
физически лежать в assets в репозитории).

### Если сборка упадёт красным крестиком

Открой Actions → упавший запуск → там будет лог с конкретной ошибкой.
Скинь мне текст ошибки — поправлю код под конкретную причину падения
(несовпадение версий, отсутствующая зависимость и т.п. — обычное дело
при первой сборке кода, который не проходил через компилятор).


- Трекинг — геометрическая интерполяция между точками, не CV-трекинг
  (нейросеть не ищет сам вотермарк на кадре, только линейно двигает
  твою рамку между отмеченными позициями).
- Нейросетевой режим требует, чтобы ты сам добавил файл модели (см. выше) —
  без него "Качественно" вызовет ошибку при первом запуске.
- Нет обработки экзотических кодеков/форматов — рассчитано на стандартный mp4.
- Код не прогонялся через компилятор в момент написания (в этом
  окружении нет Android SDK) — при первой сборке в Android Studio
  возможны мелкие правки (опечатки, несовпадение версий Gradle-плагинов
  и т.п.) — это нормально для написанного вручную кода, дай знать, если
  что-то не соберётся, разберём вместе.
