# Provider Contract

## Contents

1. Manual export
2. Automated adapter requirements
3. Preflight
4. Batch behavior
5. Failure handling

## 1. Manual export

`PROMPT_ONLY` is a complete supported path, not an error. Produce:

- prompt text;
- reference manifest and upload order;
- verified/recommended settings;
- negative prompt;
- dialogue file if useful;
- short paste-and-run instructions.

Do not claim that a provider accepts `@ImageN`; adapt labels to its actual UI or explain the upload order.

## 2. Automated adapter requirements

Only use an adapter/tool after reading its help or schema. It must expose or safely infer:

- provider and model identity;
- authentication state without printing secrets;
- supported reference types/counts;
- aspect, resolution and duration;
- price or inability to fetch it;
- submit, poll, download;
- provider job id;
- safe retry behavior;
- content-filter and balance errors.

Never fabricate endpoints, prices, model IDs or completed outputs.

## 3. Preflight

Always show:

```text
provider/model
job count
duration/aspect/resolution
reference upload order
estimated unit and maximum total cost
data destination
output path
retry/concurrency policy
manual fallback
```

Require explicit confirmation after this summary.

## 4. Batch behavior

- Start with three pilots.
- Use stable job IDs and separate output paths.
- Write checkpoint state after every success.
- Resume without repaying for completed jobs.
- Never launch two workers for the same output.
- Respect a user-defined hard budget cap.
- Limit concurrency to the provider’s published limit and the budget.
- Preserve the exact prompt/settings used for every output.

## 5. Failure handling

| Failure | Action |
|---|---|
| missing provider/tool | return manual package |
| missing key | explain local setup; never request the secret in chat |
| price unknown | do not estimate as fact; request cap or prompt-only |
| content blocked | report clearly; offer a compliant rewrite |
| network/transient | bounded retry with backoff |
| balance/limit | stop batch and preserve checkpoint |
| bad output | diagnose through FIX; do not blind-rerun repeatedly |
